uiPSF robustness review

Review of the test_roi branch of ries-lab/uiPSF (head b367f00) and of Liu et al., Nature Methods 2024. Written to start a discussion; nothing has been changed in the code. October 2026.

The main finding is that the forward model is mostly sound and the fitting is the weak part. Tuning self.weight is a symptom of that. Those weights are not loss weights. They scale the variables before L-BFGS-B sees them. If the fit converged to the true optimum, their exact values would barely matter. A synthetic test with a perfectly matched model shows exactly this. On dim beads, rescaling one variable changes the z error of the learned model from 61 nm to 5 nm, because only some scalings let L-BFGS-B converge within 200 iterations. Model mismatch in real data adds to this. It is covered in its own section below. In simulations it behaves differently: it biases the pupil the same way for every scaling and leaves a visible excess in the loss. A background gradient across the ROI and a piezo scale error were the most harmful effects tested. Both are cheap to model, in the same family as stage tilt.

Five things that would probably help robustness most

  1. Replace the hand-set variable scaling with a solver that does not depend on it. Options: Levenberg–Marquardt or Gauss–Newton on the Poisson likelihood, using the block structure (per-bead parameters plus shared pupil parameters). A cheaper first step is to scale each variable by its Fisher information at the initial guess.
  2. Make the objective stationary. The penalty factor mu grows by 1.1× on every function evaluation, including inside L-BFGS line searches. This bites only once a positivity constraint becomes active. Use L-BFGS-B's own bounds, or reparametrise (for example softplus for background and intensity), instead of ramped quadratic penalties.
  3. Fix the Poisson loss. Pixels with data ≤ 0 or model ≤ 0 are silently dropped (LL[is_finite(LL)]). Use xlogy plus a read-noise or sCMOS offset term, and sum the loss instead of averaging it, so regularisation strength does not depend on how many beads and pixels there are.
  4. Remove exact and near degeneracies. Pupil-magnitude scale vs photons is exactly degenerate. Defocus Z4 vs the common bead z offset is nearly degenerate, and so is Z11 vs depth for in-situ. Fix or orthogonalise them.
  5. Compile the graph. Every evaluation currently runs eagerly with a NumPy float32→float64 round trip. Wrapping it in tf.function/XLA, or torch.compile/JAX jit, and moving the optimiser loop onto the device is the cheapest large speed-up. A switch of framework alone gains little.

Why the weights need tuning

The bead Zernike model (PSFZernikeBased_file.py:67) sets:

weight = [wI·100, median(bg), 40/wI, 20/wI, 20/wI] # wI = sqrt(median photons) forward = psf · (I_var · w0) + bg_var · w1, phase = Σ Zk · (Z_var · w3), …

The optimiser sees I_var, bg_var and Z_var, and the weights act as a diagonal preconditioner. Three things in the current setup make the result depend on them:

  1. L-BFGS is not scale-invariant early on. It starts from an identity Hessian, so its first steps and its line-search step sizes depend on the relative scale of the variables. The loss is a mean deviance over N·Nz·L² pixels, so the gradient with respect to a shared Zernike coefficient is tiny compared with the gradients of per-bead parameters. Within 100–200 iterations the solver simply does not reach the optimum unless the scales happen to suit the data.
  2. The objective changes while it is being minimised. In optimizers.py:429, mu *= 1.1 runs once per function evaluation, capped at 1e7 (reached after about 170 evaluations). It multiplies the positivity penalties. L-BFGS curvature pairs and Wolfe line searches assume a fixed function. The result is spurious ABNORMAL_TERMINATION_IN_LNSRCH stops and stiff penalty walls late in the fit. L-BFGS-B supports bounds natively, but they are commented out (optimizers.py:291).
  3. Some regularisers act on the scaled variables. For example gxymean acts on variables[-1], and in the in-situ losses the Zernike L2 acts on zcoeff. Changing a weight therefore also changes the effective regularisation strength.

Add exact degeneracies with zero curvature (pupil magnitude vs photons) and float32 losses fed to a float64 L-BFGS (the default ftol can never be met, so runs stop on maxiter or on a line-search failure). The fit then lands at a point that depends on its path, which is what users report. The fix is to make the solver insensitive to scaling, not to search for better weights.

A. Theory

What checks out

  • Apodisation. √cos θ_imm / cos θ_med combined with the Fresnel T_p, T_s (PSFInterface_file.py:121, Suppl. Eq. 3.3) is the standard aplanatic emission-pupil factor. The 1/cos θ_med comes from the angular-spectrum (Weyl) expansion and the √cos θ_imm from the sine condition, which is also what the Stallinga/Rieger vectorial fitters use. Above the critical angle the 1/cos θ_med pole cancels against the cos θ_med in the numerator of the Fresnel coefficients. Supercritical emission enters through an imaginary k_z,med. I found nothing wrong here. What is missing is a model of the real objective's transmission roll-off near the NA edge, which the learned pupil magnitude has to absorb.
  • Vectorial model. It is an incoherent sum over three freely rotating dipoles with the correct p/s basis. The new Ex/Ey polarisation channels pick the correct three field components (dipole_field[:3] is the x-analyser response of the x, y and z dipoles).
  • Bead kernel. The Fourier transform of a uniform sphere, J_{3/2}(2πqR)/(qR)^{3/2}, is correct. So is the Gaussian blur parametrisation (σ is stored as π·σ_px, so exp(−2σ²q²) is a true Gaussian with standard deviation σ_px).
  • CZT. The Bluestein implementation has the correct padding length N+M−1.

Gaps, ranked by likely impact on robustness and accuracy

HighDegeneracies are not handled

The scale of the pupil magnitude Zcoeff[0][0] and the photon counts are exactly degenerate, and nothing fixes either one. Z4 defocus is free alongside a free z for every bead (bead model), and also alongside a free stagepos (in-situ). Because the vectorial model uses the exact k_z and Z4 is paraxial, these are only almost degenerate, which makes the problem badly conditioned without being exactly singular. Z11 vs depth behaves the same way under index mismatch. The in-focus twin-image ambiguity (Φ(k) ↔ −Φ(−k)) is broken only when emitters sample both sides of focus. Suggestion: fix Z1–Z4 (or constrain the mean bead z), normalise the pupil to unit energy, and use high-NA defocus and spherical modes orthogonalised against k_z (Booth, Neil & Wilson 1998).

HighThe noise model is not quite Poisson

The data go through (raw − offset)·gain, and then the 0.1 % quantile is shifted to zero. The loss is a Poisson deviance, but entries with data ≤ 0 (NaN from d·log d) or model ≤ 0 are removed by boolean masking. That drops the +model term exactly in the dim wings, biasing background upward and the PSF tails downward. Read noise, per-pixel sCMOS offset, gain and variance (Huang et al. 2013) and the EMCCD excess factor are not modelled. A simple robust fix is the sCMOS shifted-Poisson likelihood, (d + σ²/g²) vs (μ + σ²/g²) with xlogy. It removes the masking, keeps shapes static (which enables XLA), and makes background estimates unbiased.

MediumOne Gaussian blur stands in for several physical effects

A single constant σ absorbs pixel integration (partly handled by bin=2), the finite emission bandwidth, bead size when R = 0 is set, vibration and drift, and any residual dipole orientation. Several of these depend on z. Spectral bandwidth is cheap to model properly: sum over 3–5 wavelengths weighted by the filtered emission spectrum (only k, k_z and the Fresnel terms change). This probably explains part of the extra blur that has to be fitted.

MediumThe bead-convolution model assumes the PSF does not change shape with depth

The 3D convolution in stage-z coordinates (Suppl. Eq. 2.9/3.4) assumes that moving the emitter is the same as moving the focus. With an oil objective and beads in water or air, the emitters inside a 100–200 nm bead sit at different heights above the interface. They see different supercritical-angle coupling and focal shift. Integrating over the bead volume in the forward model (a few depth slices with k_z,med) would remove this. It matters mainly for large beads at NA ≥ 1.45.

MediumFree intensity per slice discards information

var_photon: true (the default for the Zernike model) fits one photon count per bead per slice. That removes the z-dependent collection efficiency, which carries information about supercritical emission and the pupil magnitude, and it adds N·Nz nuisance parameters. A smooth bleaching model (exponential or a low-order polynomial in slice index) keeps most of the robustness with far fewer degrees of freedom.

MediumThe pupil sampling is fixed

pupilsize: 64 is fixed. At NA 1.43 the defocus phase step at the pupil rim reaches about π per pupil pixel near |z| ≈ 2.5–3 µm, which aliases for deep in-situ data, large z ranges and Tetrapod PSFs. Choose the pupil size automatically from the NA, the z range and the ROI size.

Low–mediumIndex mismatch, field dependence and the in-situ loop
  • Index mismatch: a reduced Gibson–Lanni model with no coverslip or oil thickness deviations, so the Zernikes have to absorb those.
  • Field-dependent model: a bilinear grid of Zernike maps with a finite-difference penalty. Low-order field polynomials from nodal aberration theory are more data-efficient for sparse in-situ data.
  • In-situ loop: emitters are selected and z-binned using the current model, so the loop can confirm its own starting point (the paper notes this bias, SN4.1.5).
  • Not modelled: polarisation-dependent (Jones-pupil) aberrations from dichroics. These become relevant now that Ex/Ey channels exist.
LowNo uncertainty and no held-out validation

No error bars are reported on Zernikes or pupil, although the Fisher matrix is cheap once there is a Gauss–Newton solver. Bead localisation checks reuse the training beads. A held-out-bead deviance and z-bias would give an honest quality metric. It is also the metric any automatic tuning would need.

B. What real data contain that the model leaves out

Freely rotating emitters are assumed throughout. The question is which instrument and sample effects are missing, in the same spirit as stage tilt, which was added later for in-situ data. Each missing effect gets absorbed somewhere: by Zernikes, the blur σ, the per-slice photons or the background. That gives a biased pupil, and it also makes the loss landscape flatter and less consistent, which makes the optimiser problem above worse.

  • Mismatch and poor convergence are separate problems with different signatures. With model mismatch all three scalings converge to the same biased answer, and the final loss sits above the noise floor. With poor convergence (the dim-bead test) the answer depends on the scaling and the loss looks fine. Users who tune weights are probably fighting the second problem. The first needs physics, and the excess deviance shows where.
  • A background gradient is the most damaging of the three. It is also the cheapest to fix: a planar background with 3 parameters per bead.
  • A 5 % piezo scale error barely changes the loss but distorts the pupil 6×. Worse, the exported z axis is then 5 % off, and nothing in the fit reports it. This is the strongest argument for a fitted z scale or per-slice z offsets.
  • A 60 nm emission band is absorbed almost completely by the blur σ for bead stacks. It may matter more in-situ and over large z ranges.

These are single realisations, with 6 beads and modest mismatches, and test the bead model only. They show which way and how strongly each effect pulls. They do not quantify real data.

How to find out which ones matter on real data

Before adding physics, it pays to look at structured residuals. After a fit, average the residual (data − model)/√model in several ways. Each pattern points to a specific missing term:

  • Over beads, per slice. A common pattern means per-slice stage error, jitter or excitation fluctuation.
  • Against field position. Field-dependent aberrations.
  • Radially. Halo or flare, the blur model, ROI truncation.
  • Against z. z-dependent blur from polychromatic emission, or z-scale error.
  • Against pixel position on the sensor. Detector maps.

The deviance per pixel for each such group should be about 1 if the model is adequate. This "residual atlas" is cheap, tells the user what is wrong, and is a good thing to hand to an agent for triage.

C. Learning an excitation-dominated PSF (confocal, ISM, MINFLUX)

Most of uiPSF carries over: the pupil parametrisation, Zernikes, CZT, Fresnel coefficients, depth phase, bead kernel, Poisson loss, per-bead nuisance parameters, the multi-channel machinery and the in-situ idea. What changes is the forward model and the geometry of the data.

Forward model

Excitation field (vectorial focusing, Richards–Wolf). In the same k-space form uiPSF uses, with pupil coordinates (kx, ky) inside the NA:

E(r) ∝ Σ_k P_in(k) · e^{iΦ_mask(k)} · e^{iΦ_aberr(k)} · [ T_p (e_in·ρ̂) p̂_med + T_s (e_in·φ̂) φ̂ ] / √cos θ_imm · e^{i(k_x x + k_y y + k_z,med z − k_z,imm z_s)} I_exc(r) = |E_x|² + |E_y|² + |E_z|² # freely rotating absorber

Differences from the emission model:

  • Apodisation. Light goes the other way through an aplanatic lens. In k-space the amplitude factor becomes 1/√cos θimm instead of √cos θimm/cos θmed. The Fresnel coefficients are taken immersion→coverslip→medium.
  • Input field Pin. A Gaussian beam with an overfill ratio and a decentration (dx, dy) of the beam on the back aperture. These three parameters are cheap and matter a lot for donuts.
  • Input polarisation ein. A Jones vector with ellipticity and orientation as parameters. Circular handedness against the vortex charge decides whether the 2D donut has a zero at all (Hao 2010).
  • Known phase mask Φmask. Vortex eiφ, top-hat (π step at radius rth, a parameter), half-moon, or the actual SLM pattern. Learned aberrations go on top of it as Zernikes.
  • Incoherent floor. Iexc + ε·max(Iexc) accounts for depolarisation, scattered light and imperfect wave plates. For MINFLUX, ε is the parameter that sets precision and bias (Balzarotti 2017; Marin & Ries 2025, SimuFLUX).

Detection. For a freely rotating emitter, the effective confocal PSF is

h_eff(r) = I_exc(r; λ_exc) · [ I_det(r; λ_em) ⊗ pinhole ]

I_det is exactly the current uiPSF emission PSF, without camera-pixel integration and with the back-projected pinhole (a disc) in place of the pixel. With a 0.5–1 AU pinhole it is nearly flat over a MINFLUX probing pattern of 50–150 nm laterally, but it still shapes the axial response. For SPAD-array ISM (and ISM-FLUX), each detector element has its own pinhole offset dj: h_j(r) = I_exc(r)·I_det(r − d_j). This is a multi-channel model with a shared excitation, so uiPSF's multi-channel code fits the structure (Castello 2019; Zunino 2023; Slenders 2023/2025).

What data to learn from

  1. Fluorescent beads scanned through the focus (20–40 nm). These give an (x, y, z) raster per bead, which is the same data structure as a bead stack, so the bead pipeline can be reused. Changes:
    • Scan pixels instead of camera pixels: no pixel integration, but motion blur along the fast axis during the dwell time.
    • Scan distortion: galvo non-linearity and bidirectional line offsets.
    • Photon-counting detectors: pure Poisson, which is good, but SPAD dead time and afterpulsing at high count rates need a correction.
    • The bead size matters much more than for widefield. A 100 nm bead fills the donut zero, so the bead convolution is essential, and ε and the bead radius are correlated. Use small beads or two bead sizes.
  2. Gold beads in reflection or scattering. This is the standard for donut alignment (Gould 2012; Patton 2016). Scattering is coherent. With a large detector or no pinhole, the signal is ∝ |Eexc|² summed over components (a Rayleigh particle with isotropic polarisability), which fits the model above. With a confocal pinhole in reflection it becomes an amplitude product, so a different, coherent model is needed. 80–150 nm gold is no longer a point scatterer for the zero. I found no paper that compares gold-bead with fluorescent-bead characterisation of the same donut.
  3. In situ from MINFLUX raw data. Each localisation gives photon counts at K known beam positions (the targeted coordinate pattern, TCP). Fit the molecule positions together with the shared beam parameters (Zernikes, ε, polarisation, overfill, beam-steering calibration) under a multinomial/Poisson likelihood. This is the exact analogue of uiPSF in-situ, and SIMFLUX already estimates pattern parameters from the molecules (Cnossen 2020). I found no published in-situ phase retrieval for MINFLUX or STED beams, so this is an open opportunity. Two caveats:
    • The late iterations sample only near the zero, so the data mainly constrain curvature, ε and asymmetries (an off-centre zero from coma, anisotropic curvature from astigmatism). Early, wide-pattern iterations and the raw TCP traces are needed for the rest.
    • The beam-steering calibration (commanded vs actual EOD/AOD position: scale, rotation, non-linearity) plays the role stage tilt plays in widefield.

Pitfalls specific to excitation PSFs

  • The zero is a nearly singular feature. On a Poisson loss the few photons near the zero dominate the information about ε and the aberrations, so the loss must use raw counts, not normalised images.
  • Twin-image ambiguity. Intensity-only data leave Φ and −Φ(−k) indistinguishable without defocus diversity, so take the z-scan.
  • 3D donut sensitivity. The top-hat (3D) donut is much more sensitive to spherical aberration and depth mismatch than the vortex. Depth-dependent learning (the reduced Gibson–Lanni term) is needed, and residual zero contrast degrades with depth in practice (Moosmayer, PNAS).
  • Bias from aberrations even with a good zero. Astigmatism and coma give position-dependent bias for freely rotating dipoles, and fixed dipoles add more (Stallinga, Wang & Rieger 2026 preprint). That is one more reason to learn the actual beam rather than assume an ideal one.
  • Saturation. Fluorophore saturation at the crest of a confocal or MINFLUX beam breaks the linear Iexc assumption. Keep the calibration power low or model saturation as I/(1 + I/Isat).

Effort estimate. A focusing module (a new calpupilfield variant: input field, polarisation, mask, reversed apodisation), a scan-data loader, a product forward model and, for ISM, the multi-channel reuse. The optimiser, loss and bead kernel can be shared, so it is a moderate extension. The MINFLUX in-situ variant is a new data path and the most novel part.

D. Comparison with the TU Delft vectorial PSF (Stallinga & Rieger)

Reference implementation: vecfitcpu, the MATLAB code accompanying Hulleman, Thorsen, Stallinga & Rieger (vortex PSF, 2021; 4TU 10.4121/15175494), with vecfitcpu_zstack_bead.m for aberration retrieval from bead stacks. I read get_pupil_matrix, get_field_matrix_derivatives, get_psfs_derivatives, get_normalization, likelihood, localization/thetaupdate, create3DBead, get_rimismatchpars and funnat.

Numerical cross-check

I ported the vecfit forward model to NumPy (pupil matrix, Fresnel coefficients, apodisation, freely rotating dipole, stage-scan defocus) and compared it with uiPSF's PSFZernikeBased.genpsfmodel (vector, bin 1, no blur). The test case was NA 1.43, nimm 1.516, nmed 1.335, so it includes supercritical-angle light, with astigmatism, coma and spherical aberration, a 21×21 ROI and 41 slices over ±1 µm.

Result. The two PSF stacks agree to 2.5·10⁻⁷ of the peak (float32 precision), with and without aberrations. This holds once you account for conventions. uiPSF uses the complex-conjugate phase convention (its evanescent branch is +i, vecfit's is −i, and both are internally consistent). The two codes also swap x and y because of MATLAB's column-major meshgrid, and the image is rotated by 180°.

So the core vectorial model in uiPSF is right. In practice, Zernike coefficients cannot be compared directly between uiPSF, vecfit and SMAP. Conjugation flips the sign of every phase coefficient, and the axis swap and rotation change the sign of odd and of sin/cos terms. A documented per-mode conversion table and a shared test PSF would prevent misreadings when results are compared between labs.

Caveat: this compares against my port of the vecfit equations, not against MATLAB itself, which was not available here. The in-situ depth term (emitter inside the medium) was not cross-checked.

E. Field dependence: FD-DeepLoc, uiPSF-FD and where to take it

How FD-DeepLoc does it (Fu et al., Nat. Methods 2023)

Source: the bioRxiv version (10.1101/2022.10.14.512179) and the public FD-DeepLoc code.

  • Calibration. Thousands of bead stacks are taken over a ~180 µm FOV: 41 × 50 nm for astigmatism, 61 × 100 nm for Tetrapod. Each bead is fitted separately with a GPU vectorial MLE (Levenberg–Marquardt). Position is shared over the stack, while photons and background are free per slice, and there is a Gaussian OTF blur. There are 21 Zernike modes; piston, tilt and defocus are excluded.
  • Map. Outlier beads are removed: more than 2.5 SD from the local mean, or relative error above 15–20 %. The rest are interpolated per pixel with natural-neighbour scatteredInterpolant, which extrapolates linearly outside the convex hull of the beads. The map is then smoothed with a Gaussian (σ = 100–200 px).
  • Use. The training data for the network are simulated with the local Zernikes. CoordConv gives the network the field position, and "robust training" adds N(0, λ/100) noise to every coefficient. There is no in-situ refinement inside FD-DeepLoc. Its demo can import uiPSF insitu_FD maps instead.
ConfirmedThe uiPSF → FD-DeepLoc map import is misregistered
FD-DeepLoc fd_deeploc_core/uiPSF_abermap.py:7-11 · uiPSF PSFZernikeBased_FD_file.py:48

uiPSF places n grid nodes from 0 to the image size (spacing imsz/(n−1)). The converter treats them as sitting at 0…n−1 and samples at n/imsz per pixel, so the map is stretched by n/(n−1). The error is zero at the origin and grows to one node spacing at the far edge, which is 40 px with the default division, and more for coarse grids. Outside the grid the converter extrapolates linearly. This is a small fix, but it needs agreement between both groups.

uiPSF's FD model today

  • Representation. Every Zernike coefficient (phase and magnitude) is a grid map with imsz//division nodes per axis, interpolated bilinearly to each bead. division is pixels per node (default 40), not the number of subdivisions that the config comment and Supp. Note 3.6 describe. On a 2048 px chip that gives about 51² × 45 × 2 ≈ 230 000 parameters, constrained by tens to hundreds of beads.
  • Regularisation. A first-difference smoothness penalty with weight 0.001, acting on the scaled variables, so its strength depends on bead brightness through self.weight. It is added to a mean likelihood, so it does not weaken as more beads are added. First differences pull the maps toward constants, which biases the physically linear field trends of coma and astigmatism. Nodes with no beads nearby are set only by the penalty and their zero initial value.
  • Identifiability. The bead FD model includes a defocus map (Zk[3:]) as well as a free z per bead, which are nearly degenerate. The in-situ FD model correctly starts at Zk[4:].
  • Export. Bead FD writes the Zernike maps and per-bead models, but no spline (gencspline finds no I_model). In-situ FD exports a spline of the average PSF only.
  • Bugs.
    • genpsf builds field coordinates as (x, y) where (y, x) is expected (psflearninglib.py:639-642), so the Strehl and FWHM maps are transposed.
    • calfwhm reshapes (n+1)² samples to (ny, nx) and crashes.
    • In-situ FD with zernike_nl set computes the phase from the magnitude coefficients (_FD_smlm_file.py:184).
    • estzernike unpacks 2 of 3 return values (:254).
    • postprocess stores the corner-node piston, while the forward model uses the mean piston.
  • What it does better than the two-step method. The paper's SI shows that the global joint fit gives smoother maps where beads cluster than fitting each bead separately. That is worth keeping.

Proposal: a physically structured, joint FD model

  1. Basis. Represent each Zernike coefficient as a low-order polynomial in field coordinates around a fitted optical-axis centre (x₀, y₀), constrained by nodal aberration theory. The TU Delft funnat code uses 47 parameters for 12 modes over the whole field: astigmatism up to quartic in field, coma up to cubic, and so on. Droste et al. (Optica 2025) fit such a model directly to SMLM frames without beads. Add an optional, heavily regularised coarse residual (cubic B-spline with about 6×6 knots and a second-difference/thin-plate penalty, so linear trends cost nothing). That is roughly 50–150 parameters instead of 10⁵. It extrapolates sensibly to areas without beads and can be compared between instruments.
  2. Fitting. Keep uiPSF's joint maximum-likelihood fit. Initialise it with a quick two-step fit: Zernikes per bead or per cell (a few iterations with the shared solver), then a linear least-squares NAT fit. Report the R² of the NAT fit as a diagnostic of how well the low-order model describes the instrument.
  3. Remove the degeneracies.
    • No defocus map.
    • Treat field curvature, camera tilt and stage tilt together as a focal surface zf(x, y), shared by beads and in-situ data (section B).
    • For bead stacks, use per-bead z = zstage + zf(x, y) + a small residual.
    • Keep piston and tilt out of the maps.
    • Make the pupil magnitude field-independent by default; vignetting at the corners is at most a first-order term.
  4. Coverage and uncertainty. Export a support or uncertainty map from the Fisher matrix of the field parameters, and mask or fall back to the polynomial where there are no beads. Rule of thumb for data: at least 3–5× as many well-spread beads as field parameters (≥ 100 for NAT), with a minimum per quadrant.
  5. In-situ FD. With about 50 field parameters, in-situ data alone become usable (Droste 2025). Use the bead-calibrated FD model as a prior and refine only the low-order terms per sample, stratifying the emitter selection by field radius as well as z.
  6. Export for downstream tools. Write the analytic model (coefficients, centre, normalisation) plus optional cspline stacks per tile for SMAP, and a resampled map with a documented grid convention for FD-DeepLoc. Fix the converter and the genpsf x/y swap together with the Li lab.

F3. Performance and framework

Where the time goes

  • Everything runs eagerly. The @tf.function on objective_wrapper_for_gradient is commented out. Each evaluation re-dispatches hundreds of small ops from Python and then converts float32→NumPy→float64 for SciPy.
  • The full vectorial PSF is recomputed for every bead and slice. That is N·Nz·6 CZTs on a padded (64+2L−1)² grid. For 40 beads × 41 slices a single complex intermediate is about 0.9 GB, and the gradient tape keeps many of them. Lateral shifts could instead be phase ramps on a shared model. A per-bead z offset still needs its own defocus term, but it could be interpolated from a fine shared z grid.
  • The CZT could be a matrix multiplication. For a 64-pixel pupil and a 42-pixel output, a matrix Fourier transform (two dense matmuls, 42×64 · 64×64 · 64×42) is cheaper than three padded 105×105 FFTs and runs very well on GPU tensor cores.
  • The loss uses a boolean mask (LL[is_finite]). That gives dynamic shapes and blocks XLA compilation.
  • ROI and in-situ preprocessing has CPU hot spots. Dense overlap convolution, O(N²) Python channel pairing, a new localizationlib (DLL reload) inside the Zernike-search loop, and whole-file HDF5 reads before slicing.

PyTorch, JAX, Julia?

The framework is a second-order question. TF, PyTorch and JAX all have complex FFTs, reverse-mode autodiff and GPU support. What makes the difference is (a) compiling the whole evaluation, (b) keeping the optimiser loop on the device, (c) access to forward-mode JVPs for Gauss–Newton/LM, and (d) float64 when needed. Ranked by how well the solver tooling fits this problem (installation and GPU access per platform come next, and they change the final choice):

  1. JAX. jit + vmap over beads, jvp/vjp, and ready-made L-BFGS and Levenberg–Marquardt solvers that run on device (optimistix, jaxopt). Easy float64 switch. It is the closest to the "physics plus a good solver" structure.
  2. PyTorch. torch.compile and torch.func (jvp/vjp/vmap) cover the same ground. The ecosystem is the largest, and the EPFL vectorial-PSF library (arXiv 2502.03170) is PyTorch. Its built-in LBFGS is weaker than SciPy's, and an LM solver would have to be written.
  3. Julia. This makes sense if Keith's lab is going that way anyway. It has fast native code, Enzyme/Zygote for AD, and LsqFit/Optim. GPU support for AD through complex FFTs is less mature.

Apple GPUs have no float64, which is fine for the forward model in float32. In PyTorch's current compiler, torch.compile does not generate code for complex operators; it falls back to eager kernels for those. Compile gains for this code are therefore limited unless the field maths is written in real and imaginary parts.

How much does a GPU help? The workload is thousands of small batched FFTs or matrix DFTs (beads × slices × 6 dipole fields on 64–128 px grids), which suits GPUs. I expect roughly 10–50× over a multi-core CPU on a recent NVIDIA card, but that is unmeasured; no GPU was available here. Apple GPUs gain less: 2.5× on an M1 Pro, measured below. For reference, on 4 CPU cores one forward+backward of a uiPSF-sized PyTorch prototype (6 beads × 41 slices × 6 fields) takes 0.12 s with a matrix DFT and 0.43 s with a padded FFT. The matrix DFT is the faster formulation on CPU too. The framework-independent gains add to this: about 10× fewer iterations from a Gauss–Newton/LM solver (an estimate) and about 3× from compiling (measured on CPU in TF). With those, bead fits are fine on a laptop CPU, and the GPU matters mostly for in-situ and field-dependent learning.

Choice for a new version: PyTorch.

  • Automatic device choice: CUDA, then MPS, then CPU.
  • Matrix-DFT forward model.
  • A small Levenberg–Marquardt / Gauss–Newton solver built on torch.func JVP/VJP.
  • Pure Python, installed with pip or conda.

It also shares an ecosystem with the SUSTech fork and the EPFL psf-generator. JAX would be equally easy to write but would leave Windows and Mac users on CPU. The earlier open risk, complex autograd on Apple MPS, is cleared. docs/review_2026/scripts/gpu_backend_check.py passes on an M1 Pro (results below).

  • Matrix DFT is the formulation to use on both CPU and GPU. It is about 1.7× faster than the padded FFT on MPS and 3–4× faster on CPU.
  • A Mac GPU gives about 2.5× over its own CPU for the matrix DFT. That is useful but modest; NVIDIA cards are expected to gain much more (still unmeasured).
  • torch.compile failed on MPS with a complex128 type error. The cause is in the test script, not in PyTorch: a NumPy complex128 constant was created inside the compiled function, and MPS has no complex128. The script is fixed (constants built outside), but the Mac rerun is still to do. Inductor does not generate code for complex operators in any case, so compile gains are small unless the maths is written in real and imaginary parts. A new version should run eager by default.
  • Apple has no float64 on the GPU. The solver's linear algebra (the small Schur system) should run on the CPU in float64. This is cheap.

Autodiff, analytic or numerical derivatives? Keep autodiff. There are thousands of parameters (per-bead positions, photons and backgrounds, plus about 90 shared Zernike coefficients) and one scalar loss. Reverse mode gives the full gradient for 2–4× the cost of one forward pass, while numerical differentiation costs one forward pass per parameter and is noisy in float32. Hand-written analytic derivatives (as in the Stallinga/Smith GPU fitters) pay off for per-emitter fits with five parameters, not for this joint problem. The bigger gain is to use autodiff for Jacobian-vector products and run Gauss–Newton/LM. With a Poisson likelihood, JTWJ is the Fisher matrix. With a Schur complement over the per-bead blocks, each iteration solves only a ~90×90 system for the shared parameters, and convergence typically takes tens of iterations instead of hundreds.

Auto-tuning with Claude?

An agent loop could tune parameters. It would run the fit, read diagnostics (held-out deviance, residual images, z-bias curves, L-BFGS status), adjust the configuration and repeat. I would treat that as a diagnostic aid rather than the fix, for three reasons:

  • It needs a reliable, honest metric, and uiPSF does not have one yet: held-out beads and a deviance per pixel that is about 1 at the noise level. That metric is the first thing to build either way.
  • Tuning preconditioners by search is costly: every candidate is a full fit, and the answer differs per dataset. Removing the sensitivity is cheaper and permanent.
  • For a published method, reproducibility matters. "Claude picked these weights" is hard to defend in a Methods section. "Weights are derived from the Fisher information" is easy.

Where an agent clearly helps: triaging failed fits ("the line search failed at iteration 37, background hit the bound, beads 3 and 11 overlap"), choosing n_max/ROI/z range from the data, and writing per-microscope configs. With the honest metric in place, a small Bayesian-optimisation loop over the few remaining physical options (n_max, var_photon, bead radius) is cheap and defensible.

Proposed roadmap

  1. Benchmark first. Assemble 5–10 bead datasets that currently need tuning (including the ones from Keith's group), plus simulations with known ground truth. Metrics: Zernike error on simulations, held-out-bead deviance, z-bias and runtime. Every later change is judged against this.
  2. Bug fixes from F1 and E (ROI pairing, polarisation default, stage tilt, localize, FD export and map convention), plus a regression test of the new ROI finder against main.
  3. Loss and solver fixes inside the current code: xlogy loss with a read-noise offset, summed likelihood, L-BFGS-B bounds instead of the mu ramp, removal of the degenerate parameters, Fisher-diagonal scaling instead of self.weight, and tf.function. These are small diffs. If the benchmark shows that weight tuning is no longer needed, that is the main result.
  4. Residual atlas and the cheap physics terms (section B): per-slice shared z/xy/photon terms for beads, focal surface and nmed for in-situ, planar background, saturation mask. Add them only where the residual atlas shows a pattern on the benchmark data.
  5. Field dependence: replace the dense FD grid with a nodal-aberration-theory/low-order polynomial model plus an optional smooth residual, removing the defocus map; fix the FD export and the FD-DeepLoc import convention (section E).
  6. Solver upgrade: a block Gauss–Newton/LM with a Schur complement, plus parameter uncertainties from the Fisher matrix.
  7. Physics extensions as the benchmark motivates: polychromatic emission, depth-integrated bead model, smooth bleaching, automatic pupil sampling, Jones pupil for polarised channels.
  8. Port or rewrite (JAX or PyTorch, or alignment with Keith's Julia code) once the algorithm is settled. Porting the current algorithm would carry the robustness problems along.

Questions for discussion

Which datasets exactly fail without tuning, and which weights did people change? A list of (dataset, weight changed, why) would show whether the problem is mostly preconditioning or mostly model mismatch.
Is stage_tilt meant to be a known input (measured once per microscope) or a fitted parameter?
Do we want to keep TF at all? If Keith's group goes Julia and SUSTech went PyTorch, is a shared reference implementation with test data more valuable than a third framework?
How important is backward compatibility of the .h5 outputs (spline coefficients, pupil, Zernikes) for SMAP and other consumers?
For an excitation module: which first target? Bead scans on a confocal/ISM (easiest, reuses the bead pipeline) or MINFLUX in-situ from raw TCP counts (most novel, nothing published)? Are raw MINFLUX traces with TCP positions accessible from the instruments we use?
Field dependence: should the default bead model always be field-dependent (low-order NAT), given that most users pool beads from the whole FOV? Should we coordinate one field-model format with the Li lab (FD-DeepLoc) and TU Delft (funnat)?
Should in-situ learning share the bead solver (same loss and optimiser) so that improvements carry over automatically?
